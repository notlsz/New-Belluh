# Belluh growth playbook

The working playbook for taking Belluh into every market, ranked by value. It lives next to the code so every change to a market (a new kit, a price, a channel, a campaign result) is made and recorded in one place.

## Start here

| File | What it holds | Update when |
|---|---|---|
| [strategy.md](strategy.md) | The verdict, how markets are ranked, the wave plan, excluded markets | Waves or priorities change |
| [global-decisions.md](global-decisions.md) | Rules for every market: price ladder, channels, safety baseline, privacy, discreet mode, revenue from gifts and bookings, competitors | A global rule changes |
| [markets/](markets/) | One file per country: rank, wave, what is shipped (generated), the plan, and a log | Anything changes for that country |
| [build-list.md](build-list.md) | Product builds in priority order (KakaoTalk, Messenger, Traditional Chinese, Arabic RTL...) | A build ships or the order changes |
| [metrics-and-launch.md](metrics-and-launch.md) | Metrics per market, the 90-day launch loop, peak dates | Targets are replaced by real cohort numbers |
| [CHANGELOG.md](CHANGELOG.md) | Every change to the playbook, newest first | Every edit |
| [research/](research/) | The full reports, notes and the ranking script and data behind all of this | Never edited; add new research as new files |

## How to work on a market

1. Open its file in `markets/` (for example `markets/kr-south-korea.md`). The plan and the "3 moves" are the default next steps.
2. Do the work in the product. Most market work touches:
   - `supabase/functions/_shared/region.ts`: the country kit (local booking, delivery and gift sites, culture, price level)
   - `supabase/functions/_shared/jarvis.ts`: `LOVE_DAYS`, the romantic calendar
   - `supabase/functions/_shared/safety.ts`: `LINES`, the crisis line (verify every number at the source)
   - `src/i18n/`: UI languages
   - `supabase/functions/*-webhook`: Bella's channels
3. Run `node scripts/growth-status.mjs`. It reads the code and rewrites each market's "Shipped in the product" block and the table below.
4. Add a line to the market's Log (date, what changed, PR) and to [CHANGELOG.md](CHANGELOG.md). When real results come in (installs, partner-join rate, paid conversion), log them in the market file and replace the estimate they contradict.

## Rules for editing

- Keep the † mark on anything unverified; remove it only when you've checked the source, and add the link.
- All local prices except the US are estimates until a market has real price tests.
- Never weaken the safety baseline or discreet mode in a market to win growth.
- Excluded markets (China, Russia, sanctioned countries) stay excluded unless strategy.md is changed first, with the reason logged.
